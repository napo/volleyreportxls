## Meno copie inutili nella sincronizzazione

Quando un altro dispositivo modificava il file sul servizio durante il caricamento, oppure il caricamento non riusciva, la sincronizzazione successiva poteva creare copie inutili delle partite. Ora una modifica solo ricevuta dal servizio non viene scambiata per una modifica del dispositivo, e un conflitto vero produce una sola copia. Le modifiche non ancora caricate restano al sicuro. Le copie già create restano nell’archivio e si possono eliminare a mano.

## English

### Fewer unnecessary copies when synchronising

When another device changed the file on the service during an upload, or the upload failed, the next synchronisation could create unnecessary copies of matches. A change only received from the service is no longer mistaken for a change made on the device, and a real conflict produces a single copy. Changes not uploaded yet stay safe. Copies already created stay in the archive and can be deleted by hand.
